# Token Streaming Design

**Date:** 2026-03-25
**Scope:** `src/app.ts` only

## Goal

Stream LLM tokens to the terminal as they are generated by the `generate_answer` node, instead of waiting for the full response before printing.

## Approach

Use `graph.stream()` with `streamMode: "messages"` in place of `graph.invoke()`. LangGraph emits chunks as the LLM produces tokens. Each chunk includes the partial message content and metadata indicating which node produced it.

## Changes

### `src/app.ts`

Replace:
```ts
const result = await graph.invoke({ messages: conversationHistory });
console.log(result.answer);
```

With:
```ts
const stream = await graph.stream(
  { messages: conversationHistory },
  { streamMode: "messages" }
);

let answer = "";
let result: any = null;

for await (const chunk of stream) {
  const [message, metadata] = chunk;

  if (metadata.langgraph_node === "generate_answer") {
    const token = String(message.content);
    process.stdout.write(token);
    answer += token;
  }

  // capture final graph state for intent/sources/handle_unknown answer
  result = chunk;
}

console.log(); // newline after streamed output
```

After the loop:
- If `answer` is empty (handle_unknown path), extract answer from final state and print normally
- Push `new AIMessage(answer)` onto `conversationHistory`
- DEBUG and VERBOSE output use final state as before

## Edge Cases

| Case | Behaviour |
|------|-----------|
| `handle_unknown` | No LLM call, nothing streams. Answer extracted from final state after loop and printed normally. |
| LLM error in `generate_answer` | Fallback answer string returned by node, appears as a single non-streamed print after loop. |
| Empty input / exit commands | Unchanged — handled before the stream call. |

## Non-Goals

- No node-level status messages ("Classifying intent...", etc.)
- No changes to `graph.ts` or `tools.ts`
- No changes to eval script
