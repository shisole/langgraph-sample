# Token Streaming Design

**Date:** 2026-03-25
**Scope:** `src/app.ts` only

## Goal

Stream LLM tokens to the terminal as they are generated by the `generate_answer` node, instead of waiting for the full response before printing.

## Approach

Use `graph.stream()` with `streamMode: ["messages", "values"]` in place of `graph.invoke()`. The dual mode yields two types of chunks in the same loop:
- `"messages"` chunks — individual LLM token fragments as they arrive, tagged with node metadata
- `"values"` chunks — full state snapshots emitted after each node completes

Filtering message chunks to `generate_answer` gives token streaming. The final `"values"` chunk after the loop gives the complete state (intent, sources, answer) needed for DEBUG/VERBOSE output and conversation history.

## Changes

### `src/app.ts`

Replace:
```ts
const result = await graph.invoke({ messages: conversationHistory });

console.log("─".repeat(50));
console.log(result.answer);

if (VERBOSE && result.sources.length > 0) { ... }
conversationHistory.push(new AIMessage(result.answer));
```

With:
```ts
const stream = await graph.stream(
  { messages: conversationHistory },
  { streamMode: ["messages", "values"] }
);

let streamedAnswer = "";
let finalState: AgentStateType | null = null;
let hasStreamed = false;

console.log("─".repeat(50));

for await (const chunk of stream) {
  if (chunk[0] === "messages") {
    // message chunk: [type, [message, metadata]]
    const [, [message, metadata]] = chunk;
    if (
      metadata.langgraph_node === "generate_answer" &&
      typeof message.content === "string" &&
      message.content.length > 0
    ) {
      process.stdout.write(message.content);
      streamedAnswer += message.content;
      hasStreamed = true;
    }
  } else if (chunk[0] === "values") {
    // values chunk: [type, fullState]
    finalState = chunk[1] as AgentStateType;
  }
}

// Determine the final answer to use
const answer = hasStreamed ? streamedAnswer : (finalState?.answer ?? "");

// Close the streamed line only if tokens were printed
if (hasStreamed) {
  process.stdout.write("\n");
} else {
  // handle_unknown or LLM error fallback — print answer as a block
  console.log(answer);
}

// DEBUG and VERBOSE output from final state
if (DEBUG && finalState) {
  console.log(`\n[Intent: ${finalState.intent}]`);
}
if (VERBOSE && finalState && finalState.sources.length > 0) {
  console.log("─".repeat(50));
  console.log("Sources:", finalState.sources.join(", "));
}

console.log();

// Only push a non-empty answer to avoid corrupting conversation history
if (answer) {
  conversationHistory.push(new AIMessage(answer));
}
```

## Chunk type disambiguation

With `streamMode: ["messages", "values"]`, each iteration yields `[type, payload]`:

| `chunk[0]` | `chunk[1]` | When emitted |
|------------|-----------|--------------|
| `"messages"` | `[message, metadata]` | Each LLM token fragment |
| `"values"` | full `AgentStateType` | After **each node** completes |

A `"values"` chunk fires after every node, not only at `END`. For a normal `shopper_assistant` run that means ~5 `"values"` chunks. The `finalState` variable is overwritten on each one — after the loop it holds the state from the last completed node, which is the full final state.

## Edge Cases

| Case | Behaviour |
|------|-----------|
| `handle_unknown` | No LLM call, no message chunks emitted. `hasStreamed` stays false. Answer comes from `finalState.answer`. Printed as a single block, no extra leading newline. |
| LLM error in `generate_answer` | Fallback string returned as `state.answer` with no `messages` key. No tokens stream. `hasStreamed` stays false. Answer comes from `finalState.answer`. Printed as a block. Distinct from `handle_unknown` only in content — behaviour is identical. |
| `message.content` is not a string | Skip the chunk. Prevents `"[object Object]"` being written to stdout for non-text content blocks. |
| `graph.stream()` throws mid-run | Loop exits into the surrounding `try/catch`. `finalState` remains `null` but is never accessed — both DEBUG and VERBOSE branches are guarded by `finalState &&`. The existing catch block prints an error message as before. |
| Ctrl-C mid-stream | Async iterator aborts. `readline` teardown (`rl.close()`) is already outside the try/catch in the existing code — no change needed. |

## Non-Goals

- No node-level status messages ("Classifying intent...", etc.)
- No changes to `graph.ts` or `tools.ts`
- No changes to eval script
- Separator line (`"─".repeat(50)`) is printed before streaming begins, preserving existing visual layout
